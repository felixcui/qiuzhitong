## 开发流程
1. **开发前设计** - 理解需求，对于任何非简单的任务,做好技术实现方案设计和任务计划，将任务计划写入docs/tasks/YYYYMMDD_任务名称.md
2. **代码开发** - 遵循项目代码规范进行开发, 过程中跟踪任务进度，随时标记已完成的任务；如果事情进展不顺利，立即停止并重新计划，不要继续硬撑。
3. **代码review** - 完成代码更改后必须运行 `npm run build`, `npm run lint` 确保无类型错误
4. **功能验证** - 请完成代码后运行测试（如果有测试case），进行功能验证, 检查日志，根据情况可启动浏览器自我验证
5. **文档更新** - 完成功能后,必须生成总结文档(文件名格式：YYYYMMDD_功能名称.md),放到 docs/features 目录下, 并同步更新project 下面的 PRD.md, TECH.md 等项目文档中, 体现项目变更。

## 子代理策略
- 用于保持主上下文窗口的清洁
- 将研究、探索和并行分析工作外包给子代理
- 每个子代理执行一项任务，以实现专注执行

## 追求优雅（平衡）
- 对于非同寻常的改变：停下来问问自己“有没有更优雅的方法？”
- 如果感觉某个解决方案不够优雅：“以我现在所掌握的所有信息，实现一个更优雅的解决方案。”
- 对于简单、显而易见的解决方法，请跳过此步骤——不要过度设计。

## 自我提升循环
- 对经常犯的错误进行总结，更新到“docs/rules/lessons.md”。
- 给自己制定规则，避免犯同样的错误。

## 核心原则
- 简单至上：力求每个改动都尽可能简单，对代码的影响降到最低。
- 绝不偷工减料：找出根本原因，不搞临时补救。这是资深开发人员的标准。
- 最小化影响：变更应仅限于必要部分，避免引入错误。

## 开发命令
> 注意：以下命令需在 `web` 目录下执行

```bash
cd web

# 开发服务器
npm run dev

# 生产构建（包含类型检查）
npm run build

# 代码检查和自动修复
npm run lint

# 启动生产服务
npm run start
```
